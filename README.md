# QZero

QZero: an AI triage queue that groups support tickets by root cause and flags spikes before they become a backlog.

## The problem

Support queues fill up during growth. A single bug can produce dozens of tickets that look like separate issues, so the team answers symptoms one at a time.

Triage tools that only sort by priority miss the pattern. A founder or support lead needs to see the shared cause early enough to fix it, explain it, or alert the right team before the queue becomes a backlog.

## What it does

1. **Classifies each ticket.** QZero assigns a category and urgency, then writes a one-line summary, a theme, and a suggested reply.
2. **Groups related tickets.** Tickets with the same theme line up together, making repeated customer problems easier to spot.
3. **Detects spikes.** When enough tickets share a theme within a time window, QZero raises one alert for that spike.
4. **Estimates time saved.** It estimates saved triage time from the number of tickets processed and an assumed handling time per ticket.

## Results

Not yet measured.

The included 50 labeled tickets are synthetic: they were written to resemble realistic support issues and are not Dodo's actual tickets. When an evaluation is run, its score shows whether this approach works on those realistic examples, not on a live support queue.

## How to try it in 3 minutes

1. Complete [Setup](#setup), start the server, and open <http://127.0.0.1:8000>.
2. Select **Run 50-ticket eval**. It takes about 4 minutes because the Gemini free tier is limited to 15 requests per minute.
3. Select **Trigger spike burst**. The burst takes about 1 minute for the same rate-limit reason.
4. Read the spike alert in the alerts area.
5. Read the impact numbers, including the estimated minutes saved.
6. Open a triaged ticket to read its suggested reply.

## Key design choices

- **Shared Gemini rate limiter.** Every Gemini call goes through one limiter, so the app stays within the configured free-tier request rate.
- **Model-generated theme strings.** Spike detection groups on the theme string generated by the model. This keeps the prototype simple, but similarly worded tickets must produce consistent themes; differently phrased versions of the same issue may not group.
- **In-memory storage.** The queue exists only while the server is running. Restarting the server clears it; that is intentional for this prototype.
- **Prompt-defined urgency.** Urgency rules live in the system prompt, so changing those rules changes the app's behavior.

## Limitations

- Storage is in memory only; there is no persistence.
- There is no authentication or multi-user support.
- The evaluation data is synthetic and small (50 tickets). Accuracy on real tickets is unknown.
- Impact numbers are estimates based on an assumed handling time, not measured outcomes.
- Spike detection depends on the model producing consistent theme strings, so it can miss paraphrased versions of the same issue.
- Gemini free-tier limits apply.

## Setup

QZero requires Python 3.11 or later and a Gemini API key. Never commit a real key.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Edit .env and set GEMINI_API_KEY=YOUR_GEMINI_API_KEY
uvicorn main:app --reload
```

Then open <http://127.0.0.1:8000>.

### Environment variables

Copy `.env.example` to `.env`, then configure these values:

- `GEMINI_API_KEY`: Your Gemini API key; replace the placeholder only in your local `.env` file.
- `GEMINI_MODEL`: Preferred Gemini model name; the app falls back to `gemini-2.5-flash` if it is unavailable.
- `GEMINI_RPM_LIMIT`: Maximum Gemini requests per minute; `15` matches the intended free-tier limit.
- `GEMINI_DAILY_LIMIT`: Maximum Gemini requests the app will make in a day.
- `EVAL_SAMPLE_SIZE`: Number of synthetic labeled tickets to include in an evaluation.
- `SLACK_WEBHOOK_URL`: Optional Slack incoming-webhook URL for alerts; leave blank to keep alerts in the app only.
- `SPIKE_THRESHOLD`: Number of same-theme tickets required to declare a spike.
- `SPIKE_WINDOW_SECONDS`: Time window, in seconds, used when counting same-theme tickets.
- `MANUAL_MINUTES_PER_TICKET`: Assumed manual handling time used for the saved-time estimate.

## Project structure

```text
qzero/
├── main.py            # FastAPI app, API routes, queue state, eval, and demo workflows
├── triage.py          # Gemini classification schema, prompt, retries, and shared rate limiter
├── spike.py           # Theme normalization and spike detection
├── impact.py          # Estimated triage-time impact calculations
├── alerts.py          # In-app alerts and optional Slack webhook delivery
├── demo_data.py       # Synthetic labeled evaluation tickets and synthetic spike-burst messages
├── static/index.html  # Single-page browser interface
├── requirements.txt   # Python dependencies
├── .env.example       # Safe configuration template with placeholders
├── .gitignore          # Git ignore rules for local and generated files
└── README.md          # Project overview and setup guide
```
